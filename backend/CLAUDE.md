# Backend — FastAPI + SQLAlchemy

## Role
REST API server for LLM channel monitoring (Amazon Bedrock, Claude Platform on AWS, OpenAI Mantle/CRIS). The auto-prober and insights jobs run as
separate scheduled Fargate tasks (reusing this image), NOT in-process.

## Tech Stack
- Python 3.11
- FastAPI + Uvicorn
- SQLAlchemy 2.0 ORM + PostgreSQL 16
- boto3 (AWS Bedrock converse_stream; `bedrock` `list_foundation_model_agreement_offers` and `pricing` `get_products` in us-east-1 for the price sync, v2.30.0)
- `anthropic` SDK — Claude Platform on AWS channels (`prober.py`, `parity/runner.py`)
- `openai` SDK — OpenAI Mantle in-region + Global/US CRIS (`prober.py`, `gptbench.py`, `parity/runner.py`)
- `aws-bedrock-token-generator` — SigV4-derived bearer for Mantle `/anthropic` (`parity/runner.py`, `claude_features/transports.py`)
- `httpx` — `claude_features/transports.py` raw HTTP transports, `pricing_sync.py` Anthropic and OpenAI `pricing.md` fetches (also FastAPI TestClient in `tests/`)
- passlib + bcrypt (>=4.0, <4.1) for password hashing
- python-jose for JWT
- `sse-starlette` is in `requirements.txt` but imported nowhere — SSE endpoints use `StreamingResponse` (ADR-007)

## Key Files
- `main.py` — App entrypoint, lifespan, DB migration, admin seeding. The lifespan migration block (one transaction, `SET LOCAL statement_timeout` 30 s and `lock_timeout` 5 s, `pg_advisory_xact_lock(917350001)` released by the commit or rollback, no unlock, non-fatal) reads the catalog first and runs `ALTER TABLE … ADD COLUMN IF NOT EXISTS` only for a missing `_STARTUP_COLUMNS` column (`_add_missing_startup_columns`, v2.32.2): PostgreSQL requests ACCESS EXCLUSIVE before it looks for the column, so a no-op ALTER waited behind any open read of the table and failed after 5 s (2026-09-30, two of four startups while an Insights task held `probe_runs` and `probe_results`), rolling back the whole block. A new startup column goes into `_STARTUP_COLUMNS`, never as a bare ALTER; `_label_renames` stays as is

- `streamed_read.py` — overall time bound of the `yield_per` reads (2026-09-30 v2.32.1 review): `statement_timeout` (`database.py`) is per statement, and a `yield_per` read is a psycopg2 named cursor on PostgreSQL (DECLARE, then one FETCH statement per batch), so it only bounds each FETCH and a slow database (t4g.micro credit exhaustion) held a pool connection and a worker thread past 30 s. `stream_rows(query, what=...)` times the whole read — execution from the first `next()`, every fetch and the caller's per-row work — against `database._STATEMENT_TIMEOUT_MS` (read at call time; 0 or less = no limit, like `statement_timeout=0`); past it, it closes the inner iterator first (the ORM `Query` generator closes the result and sends `CLOSE`), logs `streamed read over the <n>s limit, aborted: <what> (elapsed <s>s, <rows> rows)` at WARNING and raises `StreamedReadTimeout`. It checks between rows, so the bound is about the limit plus one FETCH (itself capped by `statement_timeout`). Pass the unexecuted `Query` (with `.yield_per`); rows within the limit pass through unchanged. `stream_rows_or_503(query, route=...)` is the router form: `HTTPException(503, "DB 조회가 <n>초 안에 끝나지 않아 중단했습니다. 잠시 후 다시 시도해 주세요.")`. Users: `routers/reliability.py`, `efficiency.py`, `cost.py` (trend), `results.py` (stats) and `insights_runner.py`; a new `yield_per` read goes through it too

## Constraints
- `X | Y` union syntax is fine (Python 3.10+ runtime is 3.11)
- `from __future__ import annotations` is allowed in FastAPI modules (most routers use it), but every type in an endpoint or `Depends` signature must then be a module-level name: a model defined inside a function or imported only under `TYPE_CHECKING` cannot be resolved from the string annotation, and FastAPI silently treats a body parameter as a required query parameter (422)
- bcrypt must be `>=4.0,<4.1` (passlib incompatibility with 5.x)
- SQLAlchemy must be `<2.1`: 2.1 makes psycopg (v3) the default driver for plain `postgresql://` URLs, and only `psycopg2-binary` is installed, so every DB import fails (CI 2026-09-26 with 2.1.1; production image runs 2.0.54). Moving to 2.1 means adding `psycopg[binary]` or writing `postgresql+psycopg2://` in `database.py`
- All user input in HTML must use `html.escape()`
- Secrets must come from environment variables, never hardcoded
- A startup `ADD COLUMN` checks the catalog first and runs no DDL for a column that exists (`main._add_missing_startup_columns`, `pricing_seed.ensure_price_columns`): even a no-op `ADD COLUMN IF NOT EXISTS` waits for every open transaction that read the table
- A pooled connection keeps every session-level `SET` and session advisory lock after it goes back to the pool (the pool only rolls back). Inside a transaction use `SET LOCAL` and `pg_advisory_xact_lock` (lifespan migration block, `label_repair`, `pricing_seed`); on an AUTOCOMMIT connection, where `SET LOCAL` does nothing, undo the `SET` in a `finally` with `RESET` and invalidate the connection if that fails (`models.ensure_performance_indexes`). A session `pg_advisory_unlock` in a `finally` fails inside an aborted transaction and leaves the lock on the pooled connection (v2.32.2: the next task's startup then failed after `lock_timeout`; idle pool connections showed `lock_timeout` 5 s and `statement_timeout` 10 min and 1 min)
- A `yield_per` (server-side cursor) read goes through `streamed_read.stream_rows` (`stream_rows_or_503` in a router): `statement_timeout` alone bounds only each FETCH
- Timestamps are timezone-aware datetimes bound as ORM/Core parameters, never raw string literals in SQL (SQLite compares DateTime as text; `price_history` range joins depend on it)
- New Bedrock models may deprecate parameters (e.g., Opus 4.7 → no temperature)
