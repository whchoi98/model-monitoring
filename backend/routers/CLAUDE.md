# Backend Routers — API Endpoint Handlers

## Role
FastAPI router modules defining all API endpoints (18 router modules, registered in `main.py`; `pricing.py` holds two routers).
`GET /api/health` (public liveness, `{"status": "ok"}`) is defined in `backend/main.py`, not in a router.

## Files
- `auth.py` — `/api/auth/*` — login (public), register (EmailStr enforced), email approval, `/me` (JWT)
- `admin.py` — `/api/admin/*` — reset-monitoring-data, users CRUD (admin only: `username == "admin"`)
- `auto_probe.py` — `/api/auto-probe/*` — status (DB reservation + overdue state; `channel_intervals` / `channel_category_intervals` per-channel cadence, v2.29.0 — `{"anthropic": 300}` / `{"anthropic": 1800}` at the default since v2.29.1), latest (each model's latest row from completed auto runs within its own cadence window — `latest_results.py`, v2.29.0; not the rows of one run), trend, categories, anomalies?hours=&category= (automatic runs only) are public. `trigger` requires JWT and returns 202/409/503; scheduler/manual admission is serialized in `auto_prober.py`.
- `probes.py` — `/api/probes/run` — SSE streaming manual probe (JWT); `GET /api/probes/{run_id}` — past run + its results (public)
- `results.py` — `/api/results/*` — stored results query + stats (public). `stats` defaults to the last 24 h without `start_time` and `run_id` (2026-09-01 OOM), reads only its seven metric columns with `yield_per`, and without `run_id` clamps a `start_time` older than now − 31 days (History's 30 days + a day of browser clock skew) with a warning, echoing the clamped value (2026-09-30). `run_id` is `Query(None, ge=1)` on `stats` and the list: `run_id=0` used to skip both the 24 h default and the 31-day floor (the window branch tested `run_id is None`, the filter `if run_id`) and scan every retained success row, so 0 and negatives are 422 before any query (the frontend only sends a truthy `run_id`)
- `models.py` — `/api/models` — `AVAILABLE_MODELS` list (public)
- `prompts.py` — `/api/prompts/*` — prompt set CRUD + `POST /api/prompts/optimize` Bedrock OptimizePrompt, synchronous JSON (list = public; create/delete/optimize = JWT); the target id is normalized to the FM id (`bedrock:<region>:<fm-id>` → `<fm-id>`, v2.32.0)
- `chat.py` — `/api/chat/stream` — Sonnet 4.6 chatbot, 4 tools, dynamic followups (JWT)
- `insights.py` — `/api/insights/*` — list / latest (public); `POST /regenerate` (JWT, not streaming — starts a backend thread, returns `triggered` at once, lock-serialized) and `POST /stream-regenerate` (JWT, SSE). Both run `insights_runner` inside the backend process, so both check the body `window` first (`_checked_window`: the `insights_runner.parse_window` format `<n>h`/`<n>d`, longer than 0, at most 24h — the Insights panel sends 6h — else 422 before any thread, stream or query), and the stats read only `insights_runner._STATS_COLUMNS` (the five columns `compute_stats` uses) with `yield_per`; `run_once` reads run ids only, because a `ProbeRun` entity pulls every result entity of the run through `results` (`lazy="selectin"`) (2026-09-30). Those stats reads are bounded by `streamed_read.stream_rows` (below): stream-regenerate sends one `event: error` with the `StreamedReadTimeout` message, and the regenerate thread gets `run_once` = -1 and releases the lock
- `compare.py` — `/api/compare/run` — Comparison Lab: 1 prompt → N models in parallel, SSE stream (JWT)
- `cost.py` — `/api/cost/*` — summary, channel-compare, trend (`window` ≤ 30d on all three, the Cost page's longest, else 422; the trend streams with `yield_per` into the buckets, summary and channel-compare aggregate in SQL but still scan the window, 2026-09-30; the trend's streamed read is bounded by `streamed_read.stream_rows_or_503`); every row priced at the unit price in effect at its timestamp (`price_history.with_row_cost`, v2.30.0), a model without a price has a null cost, response shapes unchanged; only input and output prices enter the cost, the cache and long-context prices are display-only (v2.31.0); `_channel` maps `bedrock:<region>:<fm-id>` keys to `Bedrock <region>` (`Bedrock ap-northeast-2`, the same name as reliability and the frontend color maps; a malformed key is `Other`, v2.32.0)
- `reliability.py` — `/api/reliability/multi-channel` — family/channel success rate + error buckets; `_parse_label` channels `Anthropic (CP on AWS)`, `Bedrock Global`, `Bedrock US`, `Bedrock <aws-region>` (a Bedrock label whose parenthesis matches `_AWS_REGION_RE`, e.g. `Bedrock ap-northeast-2` for the Seoul in-region channels, v2.32.0; other non-Global Bedrock labels stay in `Bedrock US`), `OpenAI <region>`, sorted in that order by `_channel_sort_key`; `window` ≤ 7d (the page's longest, else 422), metric columns only with `yield_per` through `streamed_read.stream_rows_or_503`, `error_message` only for non-success rows (2026-09-30)
- `efficiency.py` — `/api/efficiency/score` — 0-100 weighted Token Efficiency Score per category (cost component = average per-row cost of priced success rows, v2.30.0); `window` ≤ 7d (else 422), metric columns only with `yield_per` through `streamed_read.stream_rows_or_503`, sums stay in Python in row order (SQL AVG would move `round` boundaries and split multi-label models, 2026-09-30)
- `pricing.py` — `router` `/api/pricing` (public, `build_pricing_payload`, 60 s in-process cache without `lang` in the key; the active set also carries the display-only `openai-list:<family_key>` channels, v2.31.0) and `/api/pricing/export?format=csv|md|json&lang=ko|en` (public, `Content-Disposition: attachment; filename="llm-monitor-unit-prices-YYYY-MM-DD.<ext>"`); `admin_router` `/api/admin/pricing/pending` (current and new values with the optional cache and long-context fields, a change ratio for every field set on both sides, v2.31.0), `POST /pending/{row_id}/approve`, `POST /pending/{row_id}/reject` (admin only, `effective_from` kept on approve, `warnings` when a verified price comes later in the lookup order `(effective_from, id)`, 404/409 with a Korean `detail`, `invalidate_cache()` after each — other backend tasks can lag up to 60 s; a generation counter keeps a payload built during a clear out of the cache) (v2.30.0, ADR-030)
- `analysis.py` — `/api/analysis/*` — stop-reason distribution + output-length histograms. The `/analysis` page calls both at once, and until v2.32.0 each read every success row of the window as a full `ProbeResult` (prompt and output_text included): the default 7d pair OOM-killed the 1 GiB backend task on 2026-09-30 (exit 137). Both now `GROUP BY (model_id, model_name, raw value)` with `count` and `min(id)` — stop reasons are normalized after grouping and merged, output lengths expand to `[value] * count` — so memory is models × distinct values, and ties on `model_name` and the `counts` keys follow first appearance (`min(id)`). `window` ≤ 30d (the page offers 24h, 7d, 30d; longer, 0 or less, or unreadable → 422 via `window_spec.parse_window`, the echoed `window` is the request string). Never load `ProbeResult` entities in a public aggregate endpoint, nor `ProbeRun` entities (their `results` relationship is `selectin`)
- `parity.py` — `/api/parity/*` — catalog, latest (완료 런 매트릭스 + 직전 런 대비 changes diff, s-maxage=60), evidence (셀별 증거), trigger (JWT, backend 내 백그라운드 스레드 — 스케줄 런과 달리 Fargate 아님)
- `gptbench.py` — `/api/gptbench/*` — latest (최신 **완료** 사이클 채널 스코어 카드 — 시작 후 14분 지난 사이클만 완료 — 호스트별 갈래 병렬(v2.32.0 두 갈래, v2.32.1 네 갈래) 뒤에도 그대로(15분이면 화면 사이클 나이가 프런트 `STALE_AFTER_MS` 30분을 넘는다), 21채널 v2.32.0, `fam_rank` 6.1 Sol, Astra, Sol, Luna, Terra, 5.5, 5.4), trend?hours= (사이클×채널 median 시계열, `hours` 1~168 — UI 최대 7일, 집계 7컬럼만 튜플 조회. 공개 엔드포인트라 상한이 곧 1요청 메모리 상한이다: 720h 전체 ORM 로드는 18채널에서 ~1 GB RSS로 1 GiB 태스크 OOM 위험) (public, v2.18.0)
- `features.py` — `/api/features/*` — catalog (39행×5 surface 정의), latest (완료 런 매트릭스 + 직전 런 대비 diff(kind: catalog|measured — 신규 셀, 사전판정 행은 catalog, v2.24.0) + drift), evidence (셀별 요청 스냅샷·응답 신호), trigger (JWT, backend 내 백그라운드 스레드, 6모델 1170셀 약 11분 — v2.32.0) (v2.23.0)

## Conventions
- All routers use `prefix="/api/..."` and appropriate `tags`
- A `?window=` goes through `window_spec.parse_window(window, max_window=<the page's longest window>)`: 0 or less, longer than the cap, unreadable, or so long that now − window leaves the datetime range → 422 before any query (2026-09-30)
- A `yield_per` read iterates through `streamed_read.stream_rows_or_503(query, route="GET <path> <params>")` (reliability multi-channel, efficiency score, cost trend, results stats): `statement_timeout` (`database.py`) bounds only each FETCH of the server-side cursor, so the helper bounds the whole read by the same `DB_STATEMENT_TIMEOUT_MS` and, past it, closes the cursor, logs a WARNING with the route, elapsed time and rows, and answers 503 `{"detail": "DB 조회가 30초 안에 끝나지 않아 중단했습니다. 잠시 후 다시 시도해 주세요."}` (the number is the configured limit); within the bound the response is unchanged (2026-09-30 v2.32.1 review)
- Auth-required endpoints use `Depends(get_current_user)`; admin gated on `username == "admin"`
- HTML responses (approval pages) must escape user input with `html.escape()`
- Error messages are in Korean for user-facing responses
- **SSE endpoints** (`probes`, `chat`, `insights`, `compare`) yield pre-formatted
  `"event: X\ndata: Y\n\n"` strings, so they MUST return
  `StreamingResponse(media_type="text/event-stream")` — never `EventSourceResponse`
  (it re-wraps each string as another `data:` field → malformed/double-wrapped SSE). See ADR-007.
