# ADR-029: 대시보드 모델 카드 지표 등급 — 워크로드 카테고리별 절대 임계치, 양호 파랑 / 경고 호박 / 위험 장미

- **Status**: Accepted
- **Date**: 2026-09-23
- **Related**: v2.26.0 (모니터링 개요, `HealthBadge` emerald/amber/rose 팔레트), `backend/auto_prober.py` `WORKLOAD_PRESETS`(6 카테고리), v2.28.0
- **Code**: `frontend/src/lib/metricGrade.ts`(단일 출처) + `metricGrade.test.ts`, `frontend/src/components/ModelStatusGrid.tsx`, `frontend/src/lib/i18n.ts` `monitoring.grade`, `frontend/e2e/monitoring.spec.ts`

## Context

메인 대시보드(`/`)의 모델 카드는 성공한 최신 결과의 TTFT, 총 응답시간, TPS를 숫자로만 보여 줬다(값 텍스트는
모두 `text-gray-200`). 55개 카드에서 느린 값을 찾으려면 숫자를 하나씩 읽어야 했다. 사용자 요청(2026-09-23):
**카드의 지표 값 텍스트를 등급으로 색칠 — 정상은 파란색, 경고는 주황(호박), 위험은 빨간색.**

같은 TTFT라도 워크로드마다 의미가 다르다. 자동 프로버는 5분마다 6개 카테고리 중 하나를 라운드로빈으로 돌리며
(`chat-short`, `structured`, `summarize`, `translate`, `code-gen`, `reasoning`), 카테고리마다 프롬프트와
`max_tokens`가 다르다. 예를 들어 `reasoning`의 p90 TTFT는 8.5초지만 `chat-short`는 2.7초다(아래 표). 따라서 하나의
기준으로 전 카드를 칠하면 추론 카드는 늘 빨갛고 짧은 대화 카드는 늘 파랗게 된다.

검토한 선택지(사용자에게 제시):

| 선택지 | 방식 | 장점 | 단점 |
|--------|------|------|------|
| **A. 카테고리별 절대 임계치** | 카테고리마다 고정 경고/위험 값 | 모델 간 비교 가능, 구현이 순수 함수 하나, 설명이 쉬움 | 원래 느린 모델이 자주 경고색 |
| B. 모델 자체 기준선 대비 상대 | 모델별 최근 창의 p90 등과 비교 | 모델의 "평소보다 느림"을 잡음 | 모델 간 비교 불가, 백엔드 집계 필요, 신규 모델은 기준선 없음 |
| C. A + B 병행 | 절대 색 + 상대 배지 | 둘 다 표현 | 카드에 신호가 둘이라 읽기 어려움, 구현량 최대 |

## Decision

**선택지 A를 채택한다 (사용자 선택, 2026-09-23).** 등급은 프런트엔드 순수 함수로 계산하고 임계치 표는
`frontend/src/lib/metricGrade.ts` 한 곳에만 둔다(카드 색, 툴팁, 범례 기준표가 모두 이 표를 읽는다).

### 임계치 (ms, 지연시간은 값 ≥ 경고 → 경고, 값 ≥ 위험 → 위험)

| 카테고리 | TTFT 경고 | TTFT 위험 | 총 응답시간 경고 | 총 응답시간 위험 |
|----------|-----------|-----------|------------------|------------------|
| `chat-short` (짧은 대화) | 3,000 | 8,000 | 4,000 | 10,000 |
| `structured` (JSON 추출) | 3,500 | 8,000 | 4,000 | 10,000 |
| `summarize` (요약) | 3,000 | 8,000 | 5,000 | 10,000 |
| `translate` (번역) | 3,500 | 8,000 | 8,000 | 12,000 |
| `code-gen` (코드 생성) | 5,000 | 12,000 | 7,500 | 14,000 |
| `reasoning` (추론) | 9,000 | 16,000 | 11,000 | 24,000 |
| 카테고리 없음/미지의 값 (fallback) | 5,000 | 12,000 | 10,000 | 24,000 |

- **TPS는 반대 방향, 전 카테고리 공통**: 값 < 40 tok/s → 경고, 값 < 15 tok/s → 위험.
- `null`, `undefined`, `NaN`, `±Infinity`는 `none`(회색 유지). **성공한 결과만** 등급을 매긴다.
- **표시 정밀도로 판정**: 카드는 `roundForDisplay`로 반올림한 값(TTFT ms 정수, 총 응답시간 100ms 단위 — 초 소수
  1자리로 표시, TPS 소수 1자리)을 판정한다. 원값으로 판정하면 화면 숫자와 색이 어긋난다 — 예: `chat-short` 3,960ms는
  "4.0 s"로 보이므로 경고, 9,960ms는 "10.0 s"로 위험, TTFT 2,999.6ms는 "3000"으로 경고.

### 도출 근거

2026-09-23 운영 자동 프로브 48시간치(2026-09-21 06:22 ~ 2026-09-23 06:18 UTC, `GET /api/results` 페이지 순회
26,577행 중 `status=success` 26,544행)의 카테고리별 분포:

| 카테고리 | n | TTFT p90 / p99 | 총 응답시간 p90 / p99 | TPS p1 / p10 |
|----------|---|----------------|-----------------------|--------------|
| `chat-short` | 4,473 | 2,744 / 12,068 | 3,746 / 12,612 | 33.8 / 58.3 |
| `structured` | 4,381 | 3,228 / 10,173 | 3,779 / 10,539 | 40.7 / 100.2 |
| `summarize` | 4,418 | 2,779 / 9,193 | 4,643 / 10,110 | 47.4 / 74.1 |
| `translate` | 4,478 | 3,315 / 10,058 | 7,575 / 12,156 | 53.3 / 66.3 |
| `code-gen` | 4,419 | 4,636 / 13,255 | 7,150 / 14,869 | 73.7 / 97.7 |
| `reasoning` | 4,375 | 8,490 / 17,106 | 10,919 / 25,524 | 46.5 / 63.6 |

경고는 p90 바로 위의 읽기 쉬운 값, 위험은 p99 근처의 읽기 쉬운 값으로 정했다(TTFT는 짧은 4개 카테고리의 위험을
8초로 통일). TPS는 전 카테고리의 p1(33.8~73.7)보다 낮은 40 / 15로 두어 "명백히 느린 스트림"만 잡는다.

같은 48시간 데이터에 적용한 **카드 단위 시뮬레이션**(카드의 세 지표 중 가장 나쁜 등급): 양호 89.2%, 경고 9.4%,
위험 1.4%(표시 반올림 적용 시 89.0% / 9.6% / 1.4%). 지표별로는 TTFT 92.2 / 6.5 / 1.3%, 총 응답시간
92.0 / 6.9 / 1.1%, TPS 99.3 / 0.6 / 0.1%다(TTFT 값이 없는 성공 행 2,528건은 `none`).

### 색과 접근성

- **값 텍스트에만** 색을 입힌다(라벨, 단위는 회색 유지): 양호 `text-blue-300`, 경고 `text-amber-300`, 위험
  `text-rose-400 light:text-rose-300`, 없음 `text-gray-200` (`GRADE_TEXT_CLASS`).
- **테마 CSS 변수**: `tailwind.config`가 blue/amber/rose 200~400을 `globals.css` 변수로 재매핑하므로 같은 클래스가
  다크/화이트 테마에서 각각 맞는 색이 된다. 카드 배경(gray-900/50 + hover 오버레이) 최저 대비: blue-300 다크 10.1:1,
  라이트 6.2:1, amber-300 다크 12.6:1, 라이트 4.6:1, rose-400 다크 6.7:1. 라이트의 rose-400(4.3:1)은 4.5:1에 못 미쳐
  `light:` 변형으로 rose-300(5.8:1)을 쓴다.
- **색에만 의존하지 않는다**: 경고 값 옆에 ▲, 위험 값 옆에 ◆ 모양 표지(`GRADE_MARKER`, `aria-hidden`), 범례에는
  양호 ●까지 표시.
- **툴팁**: 값의 `title`에 등급과 적용 기준(예: "경고 — 짧은 대화 기준 TTFT 3초 이상, 위험 8초 이상").
- **스크린 리더**: 카드 버튼 이름은 `aria-label`이라 내부 값이 읽히지 않으므로, 경고/위험 지표만 `sr-only` 설명
  (예: "TTFT 3200 ms, 경고 — …")으로 만들어 `aria-describedby`로 연결한다.
- **`data-grade`**: 각 값 요소에 `data-grade="normal|warning|critical|none"` — e2e(`monitoring.spec.ts`)와 자동화가
  색 클래스 대신 이 속성을 검사한다.
- **범례 + 접이식 기준표**: 카드 그리드 위 `<details>` 요약 줄("지표 등급: ● 양호 ▲ 경고 ◆ 위험 — 워크로드 카테고리별 기준",
  "기준값 보기" — "지표 등급:" 라벨도 화면에 보인다). 펼치면 6개 카테고리 + fallback의 TTFT/총 응답시간 경계와 TPS 공통 경계가 나온다. 툴팁이 없는
  터치 기기에서도 기준을 볼 수 있게 한 것이다. 문구는 `i18n.ts` `monitoring.grade`(KO/EN, 등급 이름은 언어마다
  한 번만 정의해 범례와 툴팁이 공유).
- **팔레트 구분**: 채널 건강 상태 배지(`HealthBadge`)의 emerald(정상) → amber → rose와 달리, 지표 값 등급의 양호는
  사용자 요청대로 **파랑**이다. "채널이 살아 있음"(건강)과 "값이 빠름"(등급)을 다른 색으로 구분한다.
- **등급 이름(KO)은 양호, 경고, 위험**: 초안의 `normal` 등급 한글 이름은 "정상"이었지만 채널 건강 배지(`monitoring.health.healthy`)도
  "정상"이라, 한 카드에 "✓ 정상" 배지와 ◆ 위험 값이 같이 보이면 같은 단어가 서로 반대 신호처럼 읽혔다. 그래서 지표 등급만
  "양호"로 바꿨다. "양호"는 "값이 기준 안에 있음"을 뜻해 등급의 의미에 맞고, "정상"은 채널 건강(응답 성공 여부) 전용으로
  남긴다. EN은 배지 Healthy, 등급 Normal로 이미 구분되므로 바꾸지 않았다. `metricGrade.test.ts`가 KO, EN 모두 등급 이름이
  건강 배지 이름과 겹치지 않음을 고정한다.

## Consequences

- (+) 55개 카드에서 느린 값을 색과 모양으로 바로 찾는다. 기준이 카테고리별이라 추론 카드가 늘 빨갛지 않다.
- (+) 순수 함수 + 표 하나라 백엔드, DB, API 변경이 없다. 경계값과 반올림은 vitest(경계 전수 비교 포함)로 고정했다.
- (−) **원래 느린 모델은 자주 경고색이다.** 같은 48시간 기준 경고 또는 위험 카드 비율: GPT 6 Astra (Global) 73.8%,
  (US) 67.9%, (us-west-2) 52.4%, Anthropic Claude Fable 5.1 (US) 58.7%, Bedrock Claude Fable 5 (US) 43.6%,
  (Global) 42.2%, Anthropic Claude Fable 5 (US) 25.4%. 절대 기준은 전체 카탈로그 대비 위치를 보여 주는 것이지 모델의
  이상 징후가 아니다 — 모델 자체 기준선 대비 이상은 선택지 B의 영역이며 이번에는 채택하지 않았다.
- (−) **임계치는 정적이라 주기적으로 다시 도출해야 한다.** 느린 신규 모델 편입, 워크로드 프리셋 변경, 프로브 경로
  변경 시 분포가 움직인다. 같은 방법(48시간 `/api/results`, 성공 행, 카테고리별 p90/p99, 카드 단위 시뮬레이션)으로
  재도출하고 `metricGrade.ts` 표만 고친다(프리셋 id가 바뀌면 `WORKLOAD_CATEGORY_IDS`도).
- (−) **TPS는 낮은 쪽만 판정한다.** TPS는 첫 토큰 이후 경과로 계산돼, 응답이 몇 개 청크로 한꺼번에 오면 수천
  tok/s로 부풀려진다(48시간 카테고리별 p99 1,154~17,732 tok/s, GPT 5.6 Luna 채널은 채널마다 약 180~220개 카드가
  1,000 tok/s 초과). 높은 TPS를 "더 좋음"으로 칠하지 않고, 40 / 15 tok/s 미만만 경고/위험으로 표시한다.
- (−) 등급은 최신 결과 1건 기준이라 일시적 스파이크도 경고색이 된다. 추세는 기존 추이 차트와 신뢰성 페이지로 본다.
