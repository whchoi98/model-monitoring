### 1.2 Bedrock in-region 키 스킴

- 형식: `bedrock:<aws-region>:<Bedrock FM id>`. `split(":", 2)`로 나누므로 FM id 안의 `:`는 보존된다(예: `…-v1:0`). OpenAI `openai:<region>:<id>`와 같은 모양이다.
- 라벨 형식: `Bedrock <family> (<aws-region>)`. 채널 표기는 OpenAI 인리전처럼 **소문자 리전 코드**를 쓴다.
- 호출 규칙: bedrock-runtime client는 **키에 적힌 리전**으로 만들고, converse/invoke의 `modelId`에는 **접두를 벗긴 FM id**를 넣는다. `_REGION_MAP` 기본값 us-east-1로 떨어지면 안 된다.
- `ProbeResult.model_id`, SSE 이벤트, `ParityResult.model_id`에는 **키 그대로** 기록한다(채널 단위 식별자).
- temperature 억제: `_REASONING_MODEL_PATTERNS`의 `"opus-5"`, `"sonnet-5"`가 substring으로 키 전체에 걸린다. 튜플은 바꾸지 않는다.
- 주기: `probe_cadence`, 프런트 `channelKey`는 첫 `:` 앞을 채널 키로 쓴다. 따라서 `"bedrock"`이 되고 override가 없어 기본 300초다. 코드 변경은 필요 없다.
- IAM: 두 역할 모두 `arn:aws:bedrock:*::foundation-model/*`를 이미 허용한다. 변경할 것이 없다.

```python
# OpenAI "openai:<region>:<id>"와 같은 모양 — 같은 FM id를 리전마다 부를 수 있어 리전을 키에 넣는다.
BEDROCK_INREGION_PREFIX = "bedrock:"


def _is_bedrock_inregion(model_id: str) -> bool:
    return model_id.startswith(BEDROCK_INREGION_PREFIX)


def _bedrock_target(model_id: str) -> tuple[str, str]:
    """Bedrock 채널 키 → (bedrock-runtime client 리전, converse/invoke_model에 넘길 modelId).

    - "bedrock:<region>:<id>" → (<region>, <id>) — split(":", 2)라 <id> 안의 ':'(…-v1:0)는 보존
    - "global.*" / "us.*" CRIS 프로파일 → (_REGION_MAP[접두], model_id 그대로) — 기존 동작
    - 그 밖(깨진 bedrock: 키 포함) → ("us-east-1", model_id) — 기존 폴백. 예외를 던지지 않는다
      (auto_prober 제출 루프에서 던지면 사이클 전체가 failed가 된다; 깨진 키는 오류 행 하나로 끝난다).
    """
    if _is_bedrock_inregion(model_id):
        parts = model_id.split(":", 2)
        if len(parts) == 3 and parts[1] and parts[2]:
            return parts[1], parts[2]
    return _REGION_MAP.get(model_id.split(".")[0], "us-east-1"), model_id


def _get_region_for_model(model_id: str) -> str:
    """Bedrock client 리전 — _bedrock_target의 첫 값. 이름 유지: auto_prober, stream_probe_events와
    테스트 monkeypatch(test_auto_prober_pool, test_auto_prober_timeout, test_cp_cadence)가 쓴다."""
    return _bedrock_target(model_id)[0]
```

## 6. 위험

1. **리전 오라우팅이 조용히 일어난다(가장 심각)**: 지금 `_get_region_for_model("bedrock:ap-northeast-2:…")`는 `split(".")[0]` 결과 `"bedrock:ap-northeast-2:anthropic"`을 찾지 못해 us-east-1로 폴백한다. 부분 수정이 특히 위험하다.
   - 리전만 고치면 `modelId`가 키 문자열이라 ValidationException이 난다.
   - `modelId`만 고치면 us-east-1에서 FM id를 호출한다. 온디맨드를 지원하는 리전이면 **잘못된 리전을 서울 라벨로 측정**하게 된다.
   - A-01~A-03과 A-18을 한 커밋에 넣고 A-T5로 고정한다.
2. **env 누락이면 채널이 조용히 사라진다**: `BEDROCK_OPENAI_GPT_61_SOL_MODEL_ID`가 한쪽 스택에만 있거나 이미지만 배포하면 prober나 gptbench가 3채널을 오류 없이 건너뛴다. 양쪽 스택을 digest 고정으로 배포하고 A-T6, A-T7로 고정한다. repo 전체 URI를 써야 한다(CLAUDE.md 실사고).
3. **Sonnet 5.5의 파라미터 정책을 모른다(V1, V2, V4, V5)**: Fable 5.1과 Opus 5.5가 같은 세대에서 forced tool_choice를 400으로 거부했다. 확인하지 않고 배포하면 패리티와 features 첫 런에 거짓 broken이나 드리프트가 생긴다. 마커는 substring이라 `"sonnet-5"`를 넣으면 Sonnet 5 두 채널과 서울 Sonnet 5까지 auto로 바뀐다.
4. **벤치 데드라인(D2)**: 21채널이면 사이클의 30~50%에서 6.1 Sol이 빠진다. 기존에 있던 부분 사이클 노출(14분)도 더 자주 드러나므로 C-06을 권장한다. 비용은 약 3,168호출/일 × 55.8k 토큰(대부분 캐시)이고, GPT 6 Sol 단가 기준 약 $40/일 증가다.
5. **FAMILY_ORDER 순서와 바이트 동일성**: `includes` 매칭이라 `"Claude Sonnet 5.5"`가 `"Claude Sonnet 5"`보다 뒤에 있으면 5.5 카드가 Sonnet 5 행에 섞인다. 백엔드와 프런트가 한 글자라도 다르면 pytest가 실패한다(B-01, D-01).
6. **CP 타깃 순서**: `_ANTHROPIC_TARGETS`와 `_CP_TARGETS`에서 `sonnet-5-5`가 `sonnet-5`보다 앞에 없으면 가드가 5.5를 제외한다(fail-closed). 오등록은 없지만 CP 채널이 등록되지 않는다. 두 목록은 순서가 같아야 한다(pytest).
7. **번들 간 테스트 의존**: B의 등록과 라벨 테스트는 A가, B의 FAMILY_ORDER 테스트는 D가, C의 벤치 계약 테스트는 A가 있어야 통과한다. 번들 단위로 "전체 초록"을 요구하면 안 되고, 합친 뒤 `make verify`로 판정한다.
8. **단가 이상값을 조용히 버린다**: `_plausible_long`은 경고 로그만 남기고 run 상태에는 영향이 없다. AWS가 요금표를 고치면 다음 동기화에서 long_*가 50% 게이트 없이 "enriched"로 채워진다. 기존 family의 long 값이 나중에 이상값이 되면 옛 값이 그대로 남는다(신호는 로그뿐).
9. **CP 월간 사용량 상한**: CP 호출이 시간당 108회에서 120회로 늘어난다(2026-09-23 429 이력). 상한이 다시 걸리면 `ANTHROPIC_CP_PROBE_INTERVAL_S=600`이 레버다(AutoProber와 backend 둘 다).
10. **사이클과 패리티 부하**:
    - AutoProber는 사이클당 7행이 늘어난다(worker 3, DB 풀 5 + 5).
    - 패리티 12시간 스윕에 새 행이 추가된다. Sonnet 5.5 Global은 3 surface, CP는 1, 서울 2행은 각 2, GPT 6.1 Sol 3행은 각 2. 소요와 비용이 는다.
    - features 런은 약 9분에서 약 11분이 되고, 첫 런 변경 배너에 catalog 195건이 한 번 뜬다(정상).
11. **프런트 GovCloud 하드코딩**: D-26, D-29, D-30을 빠뜨리면 Sonnet 5.5가 "US GovCloud 전용"으로 잘못 안내된다. 증거 모달의 N/A 사유는 runner가 KO `mantle_reason`을 저장하는 기존 동작이라 EN 화면에서도 KO로 보인다(기존과 같음).
12. **Mantle `None`의 의미가 다르다**: Fable 5.1(GovCloud 전용)은 영구적이지만, Sonnet 5.5 404는 온보딩이 덜 끝난 것일 수 있다. not_applicable이면 AWS가 서빙을 시작해도 매트릭스가 알려 주지 않는다(D4, 수동 재확인).
13. **stale 수치**: 55, 975, 18채널이 CLAUDE.md, README, docs, 모듈 CLAUDE.md, CDK 주석, UI 문구 약 60곳에 흩어져 있다. E 번들 마지막에 grep으로 확인한다. 과거 릴리스 기록은 바꾸지 않는다.
14. **스크래치패드가 사라진다**: `v232/offer-*.json`, `v232_sim/`, 이 문서는 세션이 끝나면 없어진다. B-T2 fixture 복사와 ADR-031 작성(근거 표 옮기기)을 먼저 끝낸다.

### 7.1 벤치 두 갈래 병렬 (C 번들, D2 대체)

- 갈래 1 **CRIS**: 유사 리전 `global`, `us` 채널(bedrock-runtime OpenAI 호환 호스트).
