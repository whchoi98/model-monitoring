# UI 개선 가능성 검토

검토일: 2026-10-21 UTC
대상: `main`, `1b69ecc`, 앱 버전 `2.34.0`

현재 UI는 공용 헤더, 검색과 상태 필터, 다국어, 테마, 조회 실패 복구가 갖춰져 있다. 개선 효과가 큰 부분은 **많은 채널을 빠르게 훑고, 문제 채널을 찾고, 선택한 모델을 비교하는 동선**이다. 현재 API가 제공하는 데이터를 활용하는 프런트엔드 작업으로 시작할 수 있다.

**프로젝트 구조와 검토 범위**

Next.js 16.3.5·React 프런트엔드가 FastAPI의 조회 API를 사용한다. 백엔드 데이터 저장소는 PostgreSQL이며, CDK는 프런트엔드·백엔드 ECS 서비스와 여섯 개 예약 작업을 정의한다. 화면 공통 동작은 `AppShell`, `AppHeader`, `Providers`에, 데이터 갱신과 오류 처리는 `useAsyncResource`, `DataState`, `RefreshControls`에 모여 있다.

이번 검토는 대시보드, 공용 메뉴·로그인, 가격표를 중심으로 코드와 Chromium 동작을 확인했다. 브라우저에는 기존 `e2e/visibility.spec.ts`의 66채널 모의 데이터를 사용했다. 아래 수치와 화면은 운영 서비스의 상태나 응답 성능을 측정한 결과가 아니다.

위치는 문서 상단을 기준으로 측정했다. 상단에 이미 “추세 보기” 바로가기가 있으므로 추세 접근이 막힌 것은 아니다. 다만 모델 카드를 훑으면서 비교하는 과정에서는 긴 목록을 오가게 된다. 카드의 실제 내용과 글꼴에 따라 높이는 달라질 수 있다.

모델을 따로 선택하지 않은 첫 차트에는 65개 시리즈가 등록됐다. 정상 데이터가 없는 시리즈도 포함한 수다. 상태 격자의 셀은 28×28px이며, 모델명은 `title`과 접근성 이름에 들어 있지만 셀 자체에는 표시되지 않는다. 1024px 메뉴는 표시 너비 1024px에 내용 너비 1044px로, 기존 가로 스크롤이 작동한다.

**권장 개선 순서**

| 우선순위 | 개선 대상 | 확인한 문제와 제안 | 구현 근거 |
|---|---|---|---|
| 1 | 모델 목록과 비교 동선 | 66개 카드를 항상 펼쳐 보여 준다. 간결한 목록 보기와 모델 계열별 접기를 제공하고, 모델을 선택하면 비교 버튼과 선택한 이름을 화면에 유지한다. | `AutoDashboard.tsx:246`, `ModelStatusGrid.tsx:106` |
| 1 | 추세 비교 | 첫 화면의 전체 시리즈와 긴 범례에서 특정 모델을 찾기 어렵다. 기존 “대표 모델” 선택을 더 잘 드러내고, 계열·채널별 비교 진입점을 제공한다. 초기 대표 선택을 도입한다면 URL에 선택을 명시한다. | `AutoDashboard.tsx:288`, `TrendChart.tsx:177` |
| 1 | 모바일 상태 격자 | 같은 모양의 작은 셀만으로는 오류가 난 모델을 식별하기 어렵다. 확인이 필요한 채널 이름을 요약 바로 아래에 표시하고, 격자에는 계열 구분과 선택한 모델 이름을 노출한다. | `MonitoringOverview.tsx:73` |
| 2 | 메뉴 구조 | 12개 메뉴가 같은 수준으로 나열된다. 대시보드와 비용 단가는 현재 순서를 유지하고, 나머지 메뉴에 탐색·검증·분석·실행 등 용도 구분을 제공한다. | `AppHeader.tsx:18` |
| 2 | 한국어 설명문 | 390px 요약 카드에서 “성공”, “미수집” 같은 단어가 중간에서 줄바꿈된다. 공통 설명문에 단어 단위 줄바꿈을 적용하고 긴 토큰의 예외 처리를 함께 둔다. 한글 글꼴을 명시하면 기기별 배치 차이도 줄일 수 있다. | `MonitoringOverview.tsx:62`, `globals.css`, `layout.tsx:2` |

가장 먼저 진행할 작업은 **확인 필요 채널의 이름 노출 → 간결한 모델 목록과 고정 비교 버튼 → 대표 모델·계열별 추세 비교** 순서다. 화면의 정보 밀도와 비교에 필요한 이동을 함께 줄일 수 있다.

**기존 동작에서 유지할 계약**

- 정상·오류·과부하·수집 지연·미수집을 구분하고, 마지막 확인 시각과 실제 수집 시각을 구분한다.
- 채널 상태의 “정상”과 지표 등급의 “양호·경고·위험”은 각각의 의미를 유지한다. 지표 임계치는 `metricGrade.ts`를 따른다.
- 빈 모델 선택은 전체 비교를 뜻한다. 대표 모델 보기를 추가하거나 강조해도 이 의미를 바꾸지 않는다.
- 검색·워크로드·기간·모델 선택은 URL 공유와 새로고침 후 복원을 유지한다.
- 가격은 `/api/pricing`에서 읽고, “비용 단가” 메뉴는 대시보드 바로 뒤에 둔다.
- 공개 조회가 인증 확인을 기다리지 않도록 하고, 실행 기능에는 기존 인증 계약을 적용한다.

**검증 결과와 한계**

| 검사 | 결과 |
|---|---|
| `make verify` | 캐시된 AWS 계정 정보를 `CDK_DEFAULT_ACCOUNT`로 지정한 실행에서 통과 |
| CDK | Jest 87개 통과, 타입 검사·합성 통과. ESLint 오류 0개, 기존 경고 3개 |
| 백엔드 | Ruff 통과, pytest 1,618개 통과·17개 건너뜀 |
| 프런트엔드 | 타입 검사 통과, Vitest 360개 통과 |
| 프로덕션 번들 | `npm run build -- --webpack` 통과 |
| Chromium | `shell`, `monitoring`, `visibility`, `pricing`의 48개 검사 통과 |
| 추가 화면 관찰 | 위 네 가지 화면 조건에서 가로 넘침과 페이지 JavaScript 오류 없음 |

기본 Turbopack 빌드는 이 실행 환경에서 임시 포트 바인딩 제한으로 실패했다. 최초 제한 환경에서는 Google Fonts 다운로드도 차단됐다. 따라서 브라우저 검증에는 Webpack으로 만든 번들을 사용했다. WebKit과 운영 AWS 리소스는 이번 검토에서 검증하지 않았다.

애플리케이션 코드와 운영 설정은 수정하지 않았다. 이 문서는 구현 전 검토 결과다.
