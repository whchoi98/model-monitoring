# UI 개선 구현 결과

검토·구현일: 2026-10-21 UTC. 작업 기준: `main`, `1b69ecc`.

66채널 목록에서 문제를 찾고 모델을 비교하는 동선을 개선했다. 기본 목록을 간결하게 표시하고, 문제 채널 이름과 상태를 요약 바로 아래에서 확인할 수 있게 했다. 선택한 모델의 비교 버튼은 스크롤 중에도 화면 아래에 유지된다.

**반영한 동작**

| 개선 | 사용 방법과 동작 |
|---|---|
| 문제 채널 요약 | 오류·과부하·지연·미수집 채널을 이름과 함께 최대 여섯 개 표시한다. 누르면 해당 모델로 목록을 좁히고 제목으로 포커스를 이동한다. 전체 확인 필요 채널을 보는 버튼도 제공한다. |
| 간결한 목록과 상세 카드 | 기본은 간결한 목록이다. “카드로” 전환하면 모델 ID와 입·출력 토큰까지 확인할 수 있다. 보기 방식은 `layout=compact|cards`로 URL에 저장한다. |
| 모델 계열별 접기 | 계열마다 채널 수와 확인 필요 수를 표시한다. 개별 또는 전체 계열을 접고 펼칠 수 있다. 검색·상태·정렬 조건이 바뀌면 조건에 맞는 계열을 다시 펼친다. |
| 고정 비교 영역 | 선택한 모델 수와 이름을 화면 아래에 유지한다. 이름 목록 펼치기, 추세 이동, 선택 해제를 제공한다. 챗봇 버튼 옆 공간을 사용하며 실제 높이만큼 페이지와 키보드 스크롤 여백을 확보한다. |
| 계열별 추세 비교 | 계열의 “채널 비교” 버튼 또는 추세 영역의 계열 선택기로 같은 계열의 채널을 비교한다. 전체·대표 모델 선택도 함께 제공한다. |
| 메뉴와 한국어 | 메뉴를 모니터링·탐색/검증·분석·실행으로 묶었다. 대시보드와 비용 단가는 첫 두 항목을 유지했다. 요약 설명문에는 한국어 단어 중간 줄바꿈을 줄이는 공통 스타일을 적용했다. |

검색, 워크로드, 기간, 모델 선택은 기존 URL 상태를 유지한다. 선택이 비어 있으면 전체 비교이며, 새로고침 후에도 명시한 선택이 복원된다. 지표 계산과 임계치는 기존 `metricGrade.ts`를 사용하고, 두 보기 방식은 같은 `ModelStatusItem`에서 값을 렌더링한다. 백엔드 API와 인증 계약은 변경하지 않았다.

**66채널 화면 비교**

기존 검토와 같은 모의 데이터를 사용했다. 모든 계열을 펼친 기본 간결 보기에서 `#model-status` 영역 전체 높이를 측정한 값이다. 운영 서비스의 응답 성능이나 데이터 상태를 측정한 결과는 아니다.

| 화면 | 기존 목록 영역 | 개선 후 | 감소 |
|---|---:|---:|---:|
| 1440px 한국어·다크 | 5,764px | 5,103px | 11.5% |
| 1024px 한국어·라이트 | 8,829px | 5,103px | 42.2% |
| 390px 한국어·다크 | 14,158px | 9,576px | 32.4% |
| 390px 한국어·라이트 | 14,158px | 9,576px | 32.4% |

390px에서는 추세 영역 시작점도 문서 상단 기준 15,630px에서 11,088px로 앞당겨졌다. 계열을 접거나 고정 비교 버튼을 사용하면 전체 목록을 끝까지 훑지 않고 추세에 접근할 수 있다. 네 가지 화면 조건에서 가로 넘침과 페이지 JavaScript 오류는 관찰되지 않았다.

**검증**

| 검사 | 결과 |
|---|---|
| `make verify` | 통과. 캐시된 계정 정보를 `CDK_DEFAULT_ACCOUNT`로 지정 |
| CDK | 타입·합성 통과, Jest 87개 통과. 기존 ESLint 경고 3개 |
| 백엔드 | Ruff 통과, pytest 1,618개 통과·17개 건너뜀 |
| 프런트엔드 | 타입 검사와 Vitest 360개 통과 |
| 빌드 | `npm run build -- --webpack` 통과 |
| 브라우저 | Chromium·WebKit 합계 148개 통과 |
| 코드 리뷰 | URL 상태, 필터, 등급 판정, 인증 흐름을 검토. 발견한 두 접근성 문제 수정 후 남은 차단 사항 없음 |

브라우저 검사는 공식 `mcr.microsoft.com/playwright:v1.63.0-noble` 컨테이너에서 네트워크를 차단하고 프런트엔드 소스를 읽기 전용으로 마운트해 수행했다. API는 기존 모의 데이터를 사용했다. 이 실행 환경의 Turbopack 포트 바인딩 제약 때문에 브라우저 검증에는 Webpack 번들을 사용했다.

새 동작 여섯 개의 검사가 기존 화면에서 실패하는 것을 확인한 뒤 구현했다. 리뷰에서 발견한 고정 비교 영역의 키보드 포커스 가림과 상태 버튼의 스크린리더 설명 누락도 별도로 재현했다. 최종 검사는 실제 Tab 이동, 비교 영역 제거 후 스크롤 여백 복원, 네 종류의 상태 설명을 포함한다. 메뉴 그룹화로 기존 가로 스크롤 검사의 대상 항목이 화면 안에 들어와, 실제로 화면 밖에 있는 분석 메뉴를 누르도록 전제조건을 갱신했다.

전체 검증의 첫 실행에서는 기존 백엔드 모의 서버의 연결이 한 차례 끊겨 로그 검사 한 건이 실패했다. 해당 검사는 단독 실행과 전체 재실행에서 통과했다. 관련 백엔드 코드는 수정하지 않았다.
